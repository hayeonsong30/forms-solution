## 1. 목적

빈 양식 PDF를 업로드한 뒤 AI 추천과 수동 편집을 통해 종이의 필기 영역을 데이터 수집 구조로 정의하는 편집기를 제공한다.

편집 결과는 다음 단계의 기준 정보가 된다.

```text
PDF 좌표 영역
+ 필드명
+ 데이터 키
+ 데이터 유형
+ 유형별 판독·정규화 규칙
+ 반복행 구조
= 필기 이미지 → 구조화 JSON 변환 규칙
```

1차 데모에서 Kotobuki 일반 양식과 ITSUWA 반복행 양식을 모두 설정할 수 있어야 한다.

## 2. 설계 원칙

1. 처음 사용하는 사람도 Add 목록에서 필드를 끌어 놓는 것만으로 시작할 수 있어야 한다.
2. PDF 좌표, 내부 ID 같은 기술 정보는 기본 화면에서 강조하지 않는다.
3. 캔버스, 필드 목록, 속성 패널은 항상 같은 선택 상태를 공유한다.
4. AI 추천은 초안이며 사용자가 확인한 항목만 확정 필드가 된다.
5. 반복행은 물리적으로 필드를 25번 복제하지 않고 하나의 열 스키마와 행 규칙으로 저장한다.
6. 입력 유형은 OCR 방식, 데이터 저장 타입, 검증 규칙을 함께 결정한다.
7. 사용자가 입력하지 않은 값과 명시적으로 false로 표시한 값을 구분한다.
8. 편집 중 실수는 실행 취소로 복구할 수 있어야 한다.

### 2.1 1차 프로토타입 저장·완료 정책

- 프로토타입에서는 사용자가 버전을 생성하거나 관리하지 않는다.
- 편집 중에는 임시 저장, 필드 추가·수정·삭제가 가능하다.
- `편집 완료`를 실행하면 양식 상태를 `인쇄 가능`으로 변경하고 편집을 잠근다.
- 편집 완료된 양식은 수정할 수 없으며 양식 관리에서 프린트만 가능하다.
- 새 버전 생성과 완료 양식 재편집은 본 제품 범위에서 설계한다.

## 4. 1차 데모 입력 유형 확정

사용자가 Add 패널에서 보는 기본 유형은 다음 여섯 가지다.

1. 텍스트
2. 숫자
3. 날짜
4. 시간
5. 체크 판정
6. 선택

반복행 그룹은 데이터 값 유형이 아니라 기존 필드들을 배열 구조로 묶는 컨테이너다.

### 4.1 텍스트

Short Text와 Long Text를 별개의 저장 타입으로 만들지 않는다. `텍스트` 유형 안에서 작성 형태를 선택한다.

| 속성 | 값 | 설명 |
|---|---|---|
| 작성 형태 | 한 줄 / 여러 줄 | OCR 이미지 분할과 검수 UI에 영향 |

현행 오른쪽 패널에는 `작성 형태`만 표시한다. 인식 언어는 서비스 기본 정책으로 일본어·한국어·영문·숫자 혼합을 허용하며 필드마다 사용자가 선택하지 않는다. 문자 정책, 최대 길이, 공백·줄바꿈 보존 같은 고급 옵션은 후속 범위다.

권장 사용:

- 한 줄: 이름, 담당자, 품목코드, 주소 일부
- 여러 줄: 목적, 비고, 작업 내용, 장문 의견

데이터 저장은 모두 문자열이다.

```json
{
  "inspector": "山田太郎",
  "item_code": "00125",
  "memo": "包装に小さな傷あり\n再確認済み"
}
```

#### 텍스트 영역에 숫자를 쓴 경우

숫자도 정상 인식한다. 텍스트는 일본어만 인식한다는 의미가 아니라 결과를 문자열로 저장한다는 의미다.

```text
텍스트 영역 필기: 12345
OCR 결과: "12345"
저장 타입: string
```

`문자 정책`에서 숫자를 금지한 경우에도 숫자를 무시하거나 삭제하지 않고 `"12345"`를 원 결과로 보존한 뒤 검수 오류를 표시한다.

숫자 계산이 필요하면 숫자 유형을 사용한다. 앞자리 0이 중요한 `00125` 같은 품목코드는 텍스트 유형을 사용해야 한다.

### 4.2 숫자

| 속성 | 값 |
|---|---|
| 숫자 형식 | 정수 / 소수 |
| 음수 허용 | 사용/미사용 |
| 소수 자릿수 | 0~6 |
| 최소·최대 | 선택 |
| 단위 | 선택, 예: kg, 個 |
| 천 단위 구분 | 허용/불허 |
| 빈칸 허용 | 사용/미사용 |

OCR 원본과 정규화 값을 분리한다.

```json
{
  "raw": "2O",
  "normalized": 20,
  "status": "review_required"
}
```

숫자로 확정할 수 없으면 임의로 0을 저장하지 않고 `null`과 검수 오류를 반환한다.

### 4.3 체크 판정

종이 필기에서는 체크 여부만 판단하는 경우와 `V/X`처럼 기호 자체가 의미를 가지는 경우가 다르다. UI 명칭은 단순 `Checkbox`보다 `체크 판정`을 권장한다.

#### 판정 방식 A: 체크 유무

```text
표시 있음 → true
표시 없음 → false 또는 null
```

허용 true 표시 예:

- ✓
- V
- ●
- 칸 채움
- 사선

#### 판정 방식 B: true/false 기호

```text
V 또는 ✓ → true
X 또는 × → false
빈칸 → null
판정 불가 → review_required
```

#### 체크 속성

| 속성 | 설명 |
|---|---|
| 판정 방식 | 체크 유무 / true·false 기호 |
| true 표시 | ✓, V, ●, 채움, 사선 중 복수 선택 가능 |
| false 표시 | X, ×, 빈칸 중 선택. true·false 기호 방식에서 사용 |
| 빈칸 처리 | false / null / 필수 오류 |
| 애매한 표시 | 항상 검수 / 가장 가까운 값 추천 |
| 선택 영역 | 박스 내부 / 영역 전체 |

기본 권장값:

```json
{
  "mode": "symbol_classification",
  "trueMarks": ["CHECK", "V"],
  "falseMarks": ["X"],
  "blankValue": null,
  "ambiguousPolicy": "review_required"
}
```

빈칸을 자동으로 false로 처리하면 `작성하지 않음`과 `명시적 불합격`을 구분할 수 없으므로, 검사 양식의 기본값은 null을 권장한다.

`합격`과 `불합격`이 별도 두 칸인 ITSUWA 구조에서는 두 체크 필드를 만들고 `동시 true 불가` 교차 검증 규칙을 적용한다.

```text
ok=true, ng=false  → 정상
ok=false, ng=true  → 정상
ok=true, ng=true   → 검수 필요
ok=null, ng=null   → 빈 행이 아니면 검수 필요
```

### 4.4 날짜·시간·선택

- 날짜는 자동 판별, `YYYY/MM/DD`, `YYYY-MM-DD`, 일본식 표기, 연도 생략 입력을 지원한다.
- 시간은 자동 판별, 24시간제, 오전·오후 12시간제, 시·분 분리 기입을 지원한다.
- 날짜 출력 기본값은 `YYYY-MM-DD`, 시간 출력 기본값은 `HH:mm`이다.
- 선택 유형 안에서 단일 선택과 다중 선택을 전환한다.
- 선택 옵션마다 표시명, 저장값, 독립 판정 영역을 정의한다.
- 단일 선택 결과는 문자열 하나, 다중 선택 결과는 저장값 배열로 저장한다.

## 6. 상단 도구 모음

상단 헤더와 도구 모음을 분리한다.

헤더는 `뒤로`, `양식명 직접 수정`, `자동 저장 상태`, `데이터 테스트`, `편집 완료` 순서다.

도구 모음은 `선택·이동`, `실행 취소·다시 실행`, `복사·붙여넣기·삭제`, `확대·축소·화면 맞춤`, `AI 자동 추천`, `페이지 이동` 순서다.

저장은 자동 임시 저장을 기본으로 하되, `편집 완료` 전까지 인쇄할 수 없다. 편집 완료 후에는 수정할 수 없다.

## 7. 왼쪽 패널

### 7.1 Add 영역

왼쪽 가장 위에 고정한다. 기본 카드:

- 텍스트
- 숫자
- 날짜
- 시간
- 체크 판정
- 선택

조작 방법:

1. 카드를 중앙 PDF의 원하는 위치로 드래그한다.
2. 드롭 위치에 기본 크기의 필드가 생성된다.
3. 필드 위에 기본 라벨이 즉시 표시된다.
4. 오른쪽 속성 패널의 필드명 입력에 자동 포커스한다.
5. 라벨을 입력하면 데이터 키를 자동 추천한다.

기본 생성값:

```json
{
  "label": "새 텍스트",
  "key": "text_001",
  "type": "text",
  "language": "ja",
  "status": "confirmed"
}
```

카드를 클릭한 경우에는 중앙의 기본 위치에 필드를 자동 배치하고 바로 선택한다. 카드를 드래그한 경우에는 PDF에서 놓은 위치에 기본 크기로 생성한다.

### 7.2 필드 목록

확정된 필드와 AI 추천 후보를 페이지별 트리로 표시한다.

```text
Page 1
├─ 신청자명          applicant_name     Text
├─ 사용일            use_date           Text
└─ 검사 내역         inspection_rows[]  Repeat
   ├─ 시간           time               Text
   ├─ 품목코드       item_code          Text
   ├─ 수량           quantity           Number
   ├─ 합격           ok                 Check
   └─ 불합격         ng                 Check
```

각 항목에 제공할 기능:

- 클릭: 캔버스의 해당 영역 선택
- 더블클릭: 해당 영역으로 확대
- 마우스를 올리면 복사·삭제 버튼 표시
- 드래그: 문서 필드 순서 변경
- 반복 그룹 클릭: 반복행 편집 팝업 열기

검색은 필드명과 데이터 키를 모두 대상으로 한다.

목록 순서는 데이터 테스트, JSON 속성, CSV·Excel 열 순서의 기준이 된다. 반복행 내부 열 순서는 기준행 필드의 왼쪽 위치를 기준으로 한다.

### 7.3 레이어 목록 정책

현행 프로토타입에서는 별도 심볼·레이어 목록을 제공하지 않는다. 왼쪽 `문서 필드` 목록이 필드 선택, 위치 찾기, 복사, 삭제, 순서 변경을 통합 담당한다. 별도 레이어 탭은 겹친 필드 선택 요구가 실제 운영에서 확인될 때 후속 검토한다.

## 8. 중앙 PDF 캔버스

### 8.0 신규 빈 양식 업로드 상태

- 양식 관리의 `빈 양식 업로드`를 선택하면 기존 예시 양식과 필드를 재사용하지 않고 빈 편집기로 진입한다.
- 중앙 문서 영역에는 PDF 드래그 앤 드롭 및 `PDF 파일 선택` 기능을 표시한다.
- PDF가 업로드되기 전까지 필드 추가, AI 자동 추천, 필드 설정은 비활성화한다.
- 지원 파일은 PDF이며 1차 데모의 최대 용량은 20MB로 한다.
- 업로드가 완료되면 중앙에 PDF 첫 페이지를 표시하고 필드 추가와 AI 자동 추천을 활성화한다.
- 신규 양식의 초기 필드 수는 0개이며 양식명은 `이름 없는 양식`으로 시작한다.

### 8.1 필드 표현

- 확정 일반 필드: 파란 실선
- 선택 필드: 진한 파란색 + 크기 조절 핸들
- AI 추천: 보라색 점선 + AI 배지
- 반복행 그룹: 초록색 외곽선
- 검증 오류: 빨간 외곽선

필드 내부 기본 표시:

```text
필드명
데이터 키 · 유형
```

낮은 확대 배율에서는 필드명만 표시한다. 내부 UUID는 고급 정보에서만 확인한다.

### 8.2 필드 빠른 도구

필드 옆에 부동 도구를 표시하지 않는다. 선택 필드 조작은 상단의 `복사·붙여넣기·삭제`와 오른쪽 하단의 `복사·반복행으로 묶기·삭제`로 제공한다.

Delete/Backspace 삭제, Cmd/Ctrl+D 복사, 방향키 이동, Shift+방향키 큰 단위 이동을 지원한다.

### 8.3 다중 선택

- Shift+클릭
- 필드 목록에서 Cmd/Ctrl+클릭

다중 선택 시 제공:

- 함께 이동
- 반복행으로 묶기
- 일괄 삭제

정렬, 같은 크기, 간격 동일 배치는 현행 프로토타입 범위에서 제외한다.

### 8.4 좌표

- 선택한 필드의 `Top`, `Left`, `Width`, `Height`를 오른쪽 `위치 및 크기` 영역에 표시한다.
- 캔버스에서 필드를 이동하거나 크기를 조절하면 숫자값도 즉시 갱신한다.
- 숫자를 직접 입력하면 캔버스의 필드 위치와 크기에 즉시 반영한다.
- 일반 사용자는 드래그 방식으로 편집하고 숫자 입력은 정밀 보정 기능으로 사용한다.

내부 저장은 페이지 기준 0~1 정규화 좌표를 사용한다.

```json
{
  "x": 0.214,
  "y": 0.331,
  "width": 0.182,
  "height": 0.041
}
```

오른쪽 고급 속성에서는 mm 또는 원본 PDF point로 변환해 볼 수 있다.

## 9. 오른쪽 속성 패널

선택 항목이 없으면 `필드를 선택하세요` 빈 상태를 표시하고, 필드가 선택되면 필드 속성을 표시한다. 별도 페이지·글로벌 설정은 제공하지 않는다.

### 9.1 기본 정보

- 필드명
- 데이터 키
- 데이터 유형
- 필수 여부

데이터 키는 필드명을 기반으로 자동 추천하지만 편집 완료 전까지 수정 가능하다. 편집 완료 후에는 데이터 키를 포함한 필드 설정을 변경할 수 없다.

### 9.2 유형별 설정

선택한 유형에 해당하는 설정만 노출한다.

- 텍스트: 한 줄·여러 줄
- 숫자: 정수·소수, 소수 자릿수, 음수, 단위, 최소·최대값
- 날짜: 입력 형식, 연도 생략 정책, 출력 형식
- 시간: 입력 방식, 허용 분 단위, 출력 형식
- 체크 판정: 판정 방식, true·false 표시, 빈칸 처리
- 선택: 단일·다중, 옵션 표시명·저장값·영역, 충돌·CSV 정책

### 9.3 OCR 설정 정책

현행 편집기 오른쪽 패널에서는 별도 OCR 설정 영역을 제공하지 않는다. OCR은 템플릿의 데이터 유형과 서버 기본 정책을 사용한다. 고객별 언어·모델·전처리 설정은 본 제품의 관리 설정 범위로 분리한다.

### 9.4 위치·크기

- Top
- Left
- Width
- Height

드래그·크기 조절과 숫자값을 양방향으로 동기화한다.

### 9.5 검증

- 필수
- 숫자 최소·최대 범위
- 날짜·시간 출력 형식
- 선택 충돌 처리
- 체크 빈칸 처리

사용자 정규식과 다른 필드 간 교차 검증 UI는 현행 프로토타입에서 제외한다.

## 10. 필드 복사

- 복사본의 필드명은 `원본명 1`, `원본명 2`, `원본명 3`처럼 원본명을 기준으로 일련번호를 자동 증가시킨다.
- 이미 번호가 붙은 복사본을 다시 복사해도 `원본명 1 1`로 만들지 않고 같은 원본명 계열의 다음 번호를 사용한다.
- 데이터 키도 필드명 번호에 대응하는 `_1`, `_2`, `_3` 접미사를 사용하며 중복 여부를 자동 검사한다.

GoCanvas처럼 선택 필드의 복사 버튼을 제공한다.

복사되는 항목:

- 필드 유형
- 크기
- 검증 설정
- 체크 표시 규칙
- 선택 옵션과 옵션별 판정 영역

새로 생성되는 항목:

- 내부 UUID
- 데이터 키
- 위치

예:

```text
원본 key: item_code
첫 복사: 필드명 `품목코드 1`, key `item_code_1`
두 번째 복사: 필드명 `품목코드 2`, key `item_code_2`
```

오른쪽 복사 버튼으로 만든 필드는 원본의 오른쪽 아래에 10px, Cmd/Ctrl+V로 붙여넣은 필드는 14px 이동하여 생성하고 바로 선택한다.

## 11. 반복행 편집

- 생성된 반복 그룹은 왼쪽 `문서 필드` 목록에서 선택할 수 있다.
- 반복 그룹을 선택하면 생성 시 사용한 설정창이 `반복행 편집` 상태로 다시 열린다.
- 그룹명, 그룹 데이터 키, 최대 행 수, 빈 행 처리 값을 수정하고 저장할 수 있다.
- 행 높이는 선택한 첫 행 필드 전체의 높이로 자동 계산하고 사용자가 숫자로 입력하지 않는다.
- 조회 전용 양식에서는 반복행 설정을 열어 수정할 수 없다.

### 11.1 생성 방법

수동 편집에서는 첫 데이터 행의 여러 필드를 선택하고 `반복행으로 묶기`를 누르는 방식을 사용한다. AI 자동 추천은 같은 반복 그룹 구조의 후보를 만들 수 있다. Add 카드에서 반복 그룹을 직접 끌어 만드는 방식은 현행 UI에서 제공하지 않는다.

```text
time, item_code, quantity, ok, ng 필드 생성
→ 다중 선택
→ 반복행으로 묶기
→ 첫 행 선택 영역 높이 자동 계산
→ 최대 행 수·빈 행 처리 설정
→ 25행 가이드 미리보기
```

### 11.2 반복행 속성

- `행 높이`를 사용자가 픽셀 숫자로 직접 입력하게 하지 않는다.
- 선택한 첫 번째 행의 필드 전체 영역을 기준행으로 사용한다.
- 기준행의 상단부터 가장 아래 필드의 하단까지를 한 행의 높이로 자동 계산하고, 이후 행에 같은 크기를 반복 적용한다.
- 자동 계산값은 `선택 영역 높이 · 31px`처럼 결과 확인용으로만 표시한다.
- 행 크기가 맞지 않으면 팝업을 닫고 첫 행 필드의 높이 또는 위치를 조정한 뒤 다시 반복행으로 묶는다.

- 그룹명
- 그룹 데이터 키
- 페이지
- 기준행 선택 영역
- 자동 계산된 행 높이(읽기 전용)
- 최대 행 수
- 빈 행 제외

### 11.3 반복행 열

선택한 첫 행의 필드들이 열 정의가 된다. 열 순서는 왼쪽 위치를 기준으로 자동 정렬하며 목록에서 변경할 수 있다.

```json
{
  "key": "inspection_rows",
  "maxRows": 25,
  "emptyRowPolicy": "exclude",
  "columns": [
    { "key": "time", "type": "text" },
    { "key": "item_code", "type": "text" },
    { "key": "quantity", "type": "number" },
    { "key": "ok", "type": "check" },
    { "key": "ng", "type": "check" }
  ]
}
```

### 11.4 중요한 저장 규칙

캔버스에 25개 행 가이드를 보여주더라도 열 필드를 25번 복제하지 않는다.

```text
금지: item_code1, item_code2, item_code3
사용: inspection_rows[0].item_code
```

### 11.5 반복행 해제

현행 프로토타입에는 반복행 해제 버튼이 없다. 실제 구현의 후속 작업으로 두되, 추가할 경우 첫 데이터 행의 일반 필드는 유지하고 그룹·행 규칙만 제거한다.

## 12. AI 자동 추천

### 12.0 프로토타입과 실제 구현의 구분

- 현행 프로토타입의 `AI 자동 추천`은 화면 흐름 확인용 모의 기능이다. 버튼을 누르면 예시 추천 필드를 추가하며 외부 AI API를 호출하지 않는다.
- 현행 프로토타입의 데이터 테스트·문서 조회 OCR도 샘플 응답과 지연 시간을 이용한 모의 동작이다.
- 실제 구현에서는 Gemini API 키를 브라우저에 저장하지 않고 서버 환경 변수로 관리한다.
- 실제 자동 매핑과 필기 OCR의 요청·응답·검증·재시도 규칙은 전체 PRD `7.7.7~7.7.20`을 기준으로 구현한다.

### 12.1 실행

현행 프로토타입에서는 상단 `AI 자동 추천`을 누르면 현재 페이지에 `시설 담당자 메모` 예시 후보 1개를 보라색 추천 필드로 추가한다. 별도의 현재 페이지·전체 페이지 선택창은 제공하지 않는다.

실제 AI 연결 구현에서는 업로드한 빈 PDF의 현재 페이지를 기본 분석 대상으로 사용한다. 다중 페이지 전체 분석은 처리 시간과 비용을 확인한 뒤 후속 옵션으로 추가한다.

처리 결과:

- 필드 영역
- 추천 필드명
- 추천 데이터 키
- 추천 유형
- 반복행 후보
- 추천 신뢰도

### 12.2 추천 검수

- 추천 항목은 보라색 점선으로 표시
- 추천 필드를 선택해 필드명·키·타입·영역 수정
- 추천 필드를 삭제하여 제외
- 사용자가 편집 완료하면 남아 있는 추천 필드를 확정 필드로 저장
- 확정 필드와 겹치면 자동 생성하지 않고 충돌 표시

AI가 추천한 데이터 키는 초안이며 중복 검사를 통과해야 한다.

## 13. 오류 검사

편집 완료 전에 다음을 검사한다.

- 필드명 누락
- 데이터 키 누락 또는 중복
- 페이지 밖 영역
- 필드 과도한 겹침
- 너무 작은 필드 영역
- 반복행 열이 그룹 영역 밖에 위치
- 행 높이 0 또는 최대 행 수 초과
- 체크 true·false 표시 규칙 충돌
- 숫자 최소값이 최대값보다 큼

오류를 클릭하면 해당 페이지와 영역으로 이동한다.

## 14. 저장과 상태

```text
AI 추천 → 추천 후보
사용자 채택/수동 생성 → 편집 중
오류 검사 통과 → 저장 가능
편집 완료 → 인쇄 가능·편집 잠금
인쇄·필기 수집 → OCR 처리에 사용
```

1차 데모에서는 임시 저장과 편집 완료를 구분한다. 현행 프로토타입은 메모리 상태로 화면 흐름을 시연하며, 실제 구현에서는 변경 시 자동 저장을 적용한다. 자동 저장 주기는 5초 debounce를 권장한다.

## 14.1 2026-08-19 프로토타입 확정 인터랙션

### 양식 관리에서 편집기 진입

| 양식 상태 | 행 선택 결과 | 작업 열 |
|---|---|---|
| Not Printable·편집 미완료 | 저장된 편집 상태와 양식명으로 편집기 진입 | 비활성 프린트만 표시 |
| Printable | 필드와 원본 양식을 조회 전용 상세로 표시 | 활성 프린트만 표시 |
| Not Printable·사용자 중지 | 필드와 원본 양식을 조회 전용 상세로 표시 | 비활성 프린트만 표시 |

- 양식 관리의 작업 열에는 프린트 버튼만 제공한다.
- 편집·상세 진입은 테이블 행 전체를 선택하여 수행한다.
- 행 안의 프린트 상태 선택창과 프린트 버튼을 누른 경우에는 행 이동을 실행하지 않는다.
- 행은 키보드 포커스를 받을 수 있고 Enter 또는 Space로 진입할 수 있어야 한다.

### 편집 화면 상단

- 양식명은 상단 제목을 클릭하여 직접 수정한다.
- 양식명 수정값은 자동 저장 대상으로 취급한다.
- `폼 테스트` 명칭은 `데이터 테스트`로 사용한다.
- 선택 필드가 있을 때 상단에 `복사`, `붙여넣기`, `삭제` 빠른 도구를 제공한다.

### 필드 키보드 조작

| 동작 | macOS | Windows |
|---|---|---|
| 복사 | Command+C | Ctrl+C |
| 붙여넣기 | Command+V | Ctrl+V |
| 빠른 복제 | Command+D | Ctrl+D |
| 삭제 | Delete/Backspace | Delete/Backspace |
| 실행 취소 | Command+Z | Ctrl+Z |

- 입력창, 선택창, 텍스트 영역에 포커스가 있을 때는 필드 단축키를 실행하지 않는다.
- 붙여넣은 필드는 원본에서 14px 이동하고 고유 내부 ID와 중복되지 않는 데이터 키를 자동 생성한다.
- 여러 필드를 복사하면 상대적인 위치와 옵션 설정을 유지한다.

### 선택 옵션별 판정 영역

1. 선택 필드의 옵션 목록에서 `영역 지정`을 누른다.
2. 중앙 문서에서 해당 체크박스 또는 선택 표시 영역을 드래그한다.
3. 옵션별로 독립적인 좌표 `x, y, width, height`를 저장한다.
4. 선택 필드가 활성화된 경우 기존 옵션 영역을 끌어서 위치를 수정할 수 있다.
5. 단일 선택은 선택값 하나, 다중 선택은 선택값 배열로 저장한다.

`확인 필요`는 편집기 상태가 아니라 실제 OCR 결과 검증 상태로 사용한다. 편집기에서는 중복 키, 페이지 밖 영역, 필수 설정 누락처럼 완료를 막는 구조 오류만 강조한다.

### 데이터 테스트와 필드 순서

- 데이터 테스트는 빈 원본 양식에서 필드와 출력 구조를 확인하는 읽기 전용 화면이다.
- CSV 헤더는 데이터 키를 사용하며 문서 필드 목록에 정의된 순서대로 생성한다.
- 필드 행을 누르면 문서의 대응 영역을 강조한다.
- 데이터 테스트 안에서는 필드 추가·삭제·순서 변경을 지원하지 않는다.
- 필드 순서와 CSV 열 순서는 편집 화면 왼쪽 `문서 필드` 목록에서 드래그하여 변경한다.
- 드래그 중인 필드는 반투명하게, 삽입 대상은 파란색 테두리로 표시한다.
- 순서를 변경하면 자동 저장하고 데이터 테스트, JSON 속성, CSV·Excel 열 순서에 즉시 반영한다.
- 조회 전용 상세에서는 필드 순서를 변경할 수 없다.

## 16. 사용 시나리오

### 16.1 텍스트 필드 추가

1. 왼쪽 Text 카드를 신청자명 영역으로 드래그한다.
2. `새 텍스트` 모형이 생성된다.
3. 오른쪽 필드명에 `신청자명`을 입력한다.
4. 데이터 키 `applicant_name`이 추천된다.
5. 작성 형태를 한 줄로 확인한다.
6. 저장한다.

### 16.2 체크 판정 추가

1. Check 카드를 합격 칸으로 드래그한다.
2. 필드명 `합격`, 키 `ok`를 입력한다.
3. true 표시 V·✓, false 표시 X, 빈칸 null을 설정한다.
4. 옆 불합격 칸에 복사하고 이름과 키를 `불합격`, `ng`로 변경한다.
5. 두 필드 동시 true 불가 규칙을 설정한다.

### 16.3 반복행 생성

1. ITSUWA 첫 행에 time, package_type, inspector, 검사 체크 필드를 만든다.
2. 모든 첫 행 필드를 다중 선택한다.
3. `반복행으로 묶기`를 누른다.
4. 그룹명 `검사 내역`, 키 `inspection_rows`를 입력한다.
5. 선택된 첫 행 필드의 상단부터 하단까지 행 높이가 자동 계산되는지 확인한다.
6. 최대 행 수를 25행으로 설정한다.
7. JSON 미리보기에서 배열 구조를 확인한다.

## 17. 수용 기준

### 레이아웃·선택

- Add의 텍스트·숫자·날짜·시간·체크·선택 유형을 PDF로 드래그해 생성할 수 있다.
- 드롭 후 필드명 입력에 자동 포커스된다.
- 캔버스·문서 필드 목록·속성 패널의 선택이 항상 일치한다.
- 목록 항목을 더블클릭하면 해당 PDF 영역으로 확대된다.
- 목록과 캔버스 양쪽에서 삭제할 수 있다.

### 필드

- 텍스트에서 숫자 필기를 문자열로 인식할 수 있다.
- 숫자 필드는 정수·소수와 범위를 검증한다.
- 체크 판정은 true, false, null, review_required를 구분한다.
- 날짜와 시간은 입력 형식과 출력 형식을 구분한다.
- 선택 필드는 단일·다중 선택과 옵션별 판정 영역을 저장한다.
- 복사된 필드는 새 UUID와 중복되지 않는 데이터 키를 가진다.
- 연속 복사된 필드명과 데이터 키는 각각 `1`, `2`, `3`과 `_1`, `_2`, `_3`으로 증가한다.

### 반복행

- 첫 행 필드를 선택해 반복행으로 묶을 수 있다.
- 25개 행을 표시해도 열당 필드 정의는 하나만 저장된다.
- 반복 그룹을 문서 필드 목록에서 선택하여 그룹명·키·최대 행·빈 행 정책을 다시 편집할 수 있다.
- 행 높이는 첫 행 필드의 전체 높이로 자동 계산되며 직접 입력하지 않는다.
- JSON 미리보기에서 배열 구조를 확인할 수 있다.

### 안정성

- 이동·크기 변경·삭제·복사·그룹화는 실행 취소할 수 있다.
- 실제 구현에서는 새로고침 후 마지막 자동 저장 상태를 복구한다.
- 중복 데이터 키와 잘못된 체크 규칙은 편집 완료를 막는다.
