## 1. 화면 개요

- **화면 ID**: `DOC-02`
- **화면 이름**: 문서 상세
- **메뉴 경로**: 문서 조회 > 조회
- **대상 사용자**: 필기 원본과 OCR 결과를 검수·확정하는 내부 담당자
- **비즈니스 목적**: 원본 이미지와 AI 인식값을 비교하여 수정하고 최종 데이터로 확정한다.
- **진입 경로**: `/documents/{documentId}`

> FRM-02에서 정의한 필드명, 데이터 키, 유형, 선택 옵션을 기준으로 값을 표시한다.

## 2. 주요 사용자 흐름 (Happy Path)

1. DOC-01에서 `[조회]` 클릭
2. 수신된 필기 원본과 문서 페이지 확인
3. AI OCR 실행
4. 좌측 원본과 우측 인식값 비교
5. 오류·미입력 값을 수정하고 자동 저장 확인
6. CSV 미리보기로 출력 구조 확인
7. `[최종 확정]` 실행
8. 필기 원본 PDF 또는 확정 데이터 CSV·Excel 다운로드

> 아직 필기 스캔이 하나도 들어오지 않은 문서(`status = printed`)는 2번 대신, `[+ AI OCR 실행]` 버튼에서 이미지 파일을 직접 선택해 업로드하면서 곧바로 OCR까지 이어서 실행한다.

## 3. 화면 구성

### 3.1 상단 액션 영역

- `[← 이전 화면으로]`: DOC-01로 이동
- 양식명과 문서 상태 표시
- 상태 배지
  - 인쇄됨: printed (아직 필기 스캔 없음)
  - 작성: received / processing / review_required
  - 확정: confirmed
  - 오류: error

**주요 버튼:**

- `[+ AI OCR 실행]`
  - printed: 버튼이 파일 선택 인풋을 감싼 형태 — 이미지 파일을 선택하면 업로드 후 곧바로 OCR까지 이어서 실행
  - received / error: 기존 이미지로 OCR만 재실행
  - 업로드 중: `이미지 업로드 중…`
  - 처리 중: `AI 처리 중… (최대 2분)`
- `[PDF]`
  - 필기된 원본 이미지를 PDF로 변환하여 다운로드
  - 확정 여부와 관계없이 필기 원본이 있으면 사용 가능
- `[CSV]`
  - 일반 문서: 현재 문서 CSV 다운로드
  - 공유 SOBP: 확정된 가상번호별 문서 CSV ZIP 다운로드
- `[Excel]`
  - 일반 문서: 현재 문서 Excel 다운로드
  - 공유 SOBP: 확정된 가상번호별 문서 Excel ZIP 다운로드
- `[최종 확정]`
  - review_required: 활성
  - confirmed: 미노출
  - 그 외 상태: 비활성
- `[↻ 다시 실행 (데모)]`
  - `NEXT_PUBLIC_DEMO_MODE`가 켜져 있고 원본 이미지가 있을 때만 노출
  - 상태 전이 제한 없이 OCR 재실행 (확정된 문서도 대상)
  - 데모 모드가 꺼져 있으면 API 자체가 `403 DEMO_MODE_DISABLED`로 막는다

**내보내기 제한:**

- 확정되지 않은 문서는 CSV·Excel 다운로드 불가
- 서버가 `409 NOT_CONFIRMED`로 차단
- 화면 메시지: `확정되지 않은 문서는 내려받을 수 없습니다.`
- PDF는 데이터 확정 여부와 무관하며 필기 원본 존재 여부만 확인

### 3.2 필기 원본 PDF 다운로드

**공통 규칙:**

- 다운로드 대상: 펜 데이터로 수신한 필기 원본 이미지
- OCR 박스, 인식값, 검수 상태 등 화면 오버레이는 PDF에 포함하지 않음
- 페이지 이미지를 원본 비율로 PDF 페이지에 배치
- 필기 원본이 없으면 PDF 버튼 비활성

**일반 문서:**

- 양식 1부에 포함된 모든 필기 페이지를 PDF 1개로 생성
- 양식 페이지 순서대로 정렬
- 3페이지 양식이면 필기된 1~3페이지를 합친 3페이지 PDF 다운로드
- 페이지별 SOBP가 달라도 같은 문서에 속하므로 하나의 PDF로 제공
- 파일명: `{양식명}_{문서번호}.pdf`

**공유 SOBP 문서:**

- 같은 SOBP로 묶인 가상번호별 필기 이미지를 PDF 1개로 생성
- 가상번호 오름차순으로 정렬
- 가상번호 1~3이 있으면 세 문서를 합친 3페이지 PDF 다운로드
- 모든 페이지의 SOBP는 동일하지만 가상번호로 순서를 구분
- 파일명: `{양식명}_{SOBP}.pdf`

> **현재 구현 차이**: 현재 소스는 일반 문서에서 빈 양식 PDF를 열고, 공유 SOBP 문서는 원본 이미지 ZIP을 내려준다. 필기 원본 이미지를 하나의 PDF로 생성하는 기능은 추가 구현이 필요하다.

### 3.3 페이지·SOBP 영역

- 구성: 페이지 라벨, 이전, No. 선택, 다음, SOBP 값, (printed 상태에서만) `다시 받기` 링크
- 한 페이지여도 영역을 표시하며 이전·다음 버튼 비활성
- 첫 페이지: 이전 비활성
- 마지막 페이지: 다음 비활성

**일반 다중 페이지:**

- 같은 문서 안에서 선택 페이지 변경
- 페이지별 이미지와 필드 표시
- `pageNcodes`의 현재 페이지 SOBP 표시

**공유 SOBP:**

- `No.`에 실제 가상번호 표시
- No. 변경 시 해당 가상번호 문서로 이동
- 가상번호 문서는 모두 동일한 SOBP 사용
- 이전·다음 버튼은 가상번호 오름차순으로 이동

> **미구현**: 사용자가 필기한 가상번호 저장·정렬 기능은 아직 없다.

**다시 받기 (DOC-02 자체 기능, FRM-01의 일괄 다운로드와는 별개):**

- 노출 조건: `doc.status === "printed"`일 때만 (SOBP 값 오른쪽에 점선 밑줄 텍스트 링크로 표시)
- 툴팁 문구: `같은 SOBP로 아직 인쇄만 하고 필기 스캔은 안 들어온 경우에만 다시 받을 수 있습니다.`
- 클릭 시 해당 문서 SOBP로 만든 빈 양식 PDF(`/api/templates/{templateId}/pdf`)를 다시 다운로드
- 파일명: `{양식명}_{ncode ?? documentId}.pdf`
- 진행 중 라벨: `받는 중…`
- 별도의 성공·실패 안내 메시지는 없다 — 요청이 실패하면 조용히 중단된다
- 이미 필기 스캔이 하나라도 들어온 문서(received 이후)에서는 노출되지 않는다 — 같은 SOBP로 또 인쇄물을 내려주면 공유 SOBP 문서처럼 예전 스캔과 새 스캔이 뒤섞여 구분이 안 되기 때문

### 3.4 좌측 패널 — 작성 원본

- 전체 화면 폭의 약 45%
- 원본 이미지가 있으면 현재 페이지 이미지 표시
- 원본 이미지가 없으면 `작성 원본 이미지가 없습니다.` 표시
- 원본 이미지도 없고(예: printed 상태) 양식 PDF를 불러올 수 있으면, 빈 양식 PDF 1페이지를 대신 표시

**뷰어:**

- 이미지가 있을 때 축소·확대 제공
- 줌 범위: 30~200%, 5% 단위
- 작업 영역 내부 스크롤
- 현재 페이지 필드 박스를 이미지 위에 표시
  - 기본: 필드 영역 표시
  - 활성: 파란 이중 테두리
  - 미입력·오류: 주황색 강조
- 박스 클릭 시 우측 해당 필드로 이동하고 강조
- 하단 안내
  - `오른쪽 필드값을 누르면 원본 위치가 표시됩니다.`

### 3.5 우측 상단 — 인식된 필드값

- 제목: `인식된 필드값`
- 안내: `OCR 결과를 확인·수정한 후 최종 확정합니다.`
- received / error 상태에서 `[↻ OCR 다시 실행]` 표시
- 필터 없이 전체 필드를 항상 나열
- 필드가 없으면 `해당하는 필드가 없습니다.` 표시

**필드 행:**

- 필드명과 필수 표시(`*`)
- 데이터 키와 유형
- 값 입력 컨트롤
- 상태 태그
- 검수 필요 사유
- 행 정렬 기준: `rowIndex` 오름차순 → 캔버스 위치(필드의 `boxY`, `boxX`) 오름차순 → 반복행 열 `orderNo` 오름차순으로 고정. 일반 필드는 `rowIndex`가 모두 같아 예전에는 조회할 때마다 순서가 흔들리는 문제가 있었는데, 캔버스 좌표를 2차 정렬 기준으로 추가해 항상 같은 순서로 나오도록 고쳤다.

| 유형 | 입력 방식 |
|---|---|
| 텍스트·숫자 | 텍스트 입력, 포커스 이탈 시 저장 |
| 날짜 | 날짜 입력 |
| 시간 | 시간 입력 |
| 체크 | 빈값 / true / false 선택 |
| 단일 선택 | Select |
| 다중 선택 | 체크박스 목록 |

- 선택 옵션이 없으면 `선택지가 정의되지 않았습니다.` 표시
- OCR 전 FieldValue가 없으면 입력 비활성
- 초기 표시 우선순위: `finalValue → normalizedValue → rawOcrValue`

**상태 태그:**

| 상태 | 표시 |
|---|---|
| OCR 미실행 | OCR 전 |
| 검수 필요 | 미입력·오류 |
| 검증 통과 | 완료 |
| 저장 직후 | ✓ 저장됨 |

**자동 저장:**

- 값 변경 시 FieldValue 수정 API 호출
- 텍스트·숫자는 포커스 이탈 시 저장
- 선택·날짜·시간 등은 변경 즉시 저장
- 저장 후 유형별 정규화·검증 재실행
- 사용자 수정값은 `valueSource = user`
- 오류가 없으면 `reviewStatus = confirmed`
- 저장 성공 시 상태 태그 자리에 `✓ 저장됨`이 약 1.5초 동안 대신 표시되고, 이후 원래 상태 태그(OCR 전 / 미입력·오류 / 완료)로 돌아간다. 저장 API가 실패하면(예: 문서가 이미 confirmed) 이 표시는 뜨지 않는다.
- 문서가 confirmed이면 모든 입력 비활성
- 서버도 `409 DOCUMENT_CONFIRMED`로 수정 차단

**검수 사유:**

- 필수값 누락
- 형식 오류
- 숫자 범위 초과
- 날짜·시간 형식 오류
- 정의되지 않은 선택지
- 선택값 충돌
- AI 인식 없음 — 직접 확인 필요

### 3.6 우측 하단 — CSV 자동 생성

- 제목: `CSV 자동 생성`
- 안내: `데이터 키가 열 이름으로 사용됩니다.`
- `{n}개 열 · 1건` 표시
- 헤더: 필드 데이터 키
- 값: `finalValue → normalizedValue → rawOcrValue` 순으로 미리보기

**표시 규칙:**

- `finalValue` 있음: 일반 텍스트
- `finalValue` 없음: 회색 기울임과 옅은 주황 배경
- 미확정 툴팁: `AI 인식값 미리보기 — 아직 확정 전이라 다운로드에는 포함되지 않습니다.`
- 미확정 값이 있으면 범례 표시
- 실제 다운로드는 `finalValue`만 사용
- 열이 많으면 표 아래 사용자 정의 가로 스크롤바 표시

## 4. OCR 실행·검수

### 4.1 OCR 처리

- received 또는 error 상태에서 실행 가능 (printed 상태는 이미지 업로드가 선행되어야 실행됨)
- 실행 중 문서 상태: processing
- 화면은 별도 폴링하지 않고 요청 완료 후 최신 데이터 재조회
- 성공: review_required
- Gemini 호출 실패: error
- 잘못된 상태에서 실행: `409 INVALID_TRANSITION`

**AI 미실행 처리:**

- API 키 또는 이미지가 없으면 모든 필드를 수동 검수 대상으로 생성
- `AI 인식 없음 — 직접 확인 필요` 표시
- 문서는 review_required로 전환

### 4.2 최종 확정

- review_required에서만 실행 가능
- 요청: `POST /api/documents/{documentId}/confirm`
- 필수값이 비어 있으면 확정 실패
- 실패 메시지: `확인이 필요한 값이 남아 있어 확정할 수 없습니다. 아래 표에서 강조된 항목을 채우세요.`
- 선택 필드 등 선택 항목의 검수 사유만 남아 있는 경우 확정을 차단하지 않음
- 성공
  - 문서 상태: confirmed
  - `confirmedAt` 저장
  - 필드 입력 비활성
  - CSV·Excel 다운로드 가능

> 확정을 다시 검수 상태로 변경하는 `reopen` API는 존재하지만, 현재 이 API를 호출하는 화면이 어디에도 없다 — 순수 죽은 코드다. 확정된 문서의 필드는 재검수 절차 없이 그대로 잠긴다(2026-08-27 결정).

### PDF

- 필기 원본 이미지를 다운로드
- OCR 결과와 화면 오버레이는 포함하지 않음
- 확정 전에도 다운로드 가능
- 일반 문서: 양식 페이지 순서대로 합친 단일 PDF
- 공유 SOBP: 가상번호 순서대로 합친 단일 PDF

### CSV

- 확정된 `finalValue`만 사용
- 일반 문서: 단일 CSV
- 공유 SOBP: 확정된 가상번호별 문서 CSV를 ZIP으로 제공

### Excel

- 확정된 `finalValue`만 사용
- 일반 문서: 시스템 기본 Excel
- 공유 SOBP: 확정된 가상번호별 문서 Excel을 ZIP으로 제공

> **미구현**: FRM-03에서 등록한 고객 Data Template은 메인 DOC-02 Excel 다운로드에 적용되지 않는다. 현재 고객 서식 출력은 Simple 문서 상세에서만 사용한다.

## 8. 구현 참고

- OCR은 현재 첫 페이지 이미지만 처리
- 확정 후 재검수 API는 존재하지만 UI 미연결
- 공유 SOBP 가상번호와 그룹 확정 단위는 별도 정책 확정 필요
- 메인 DOC-02와 고객 Excel 서식 출력 API 통합 필요
- 필기 원본 이미지를 페이지 순서대로 합치는 PDF 생성 API 구현 필요
- 필드값 목록 정렬은 `rowIndex` → 필드 캔버스 좌표(`boxY`, `boxX`) → 반복행 열 `orderNo` 순으로 고정되어 있다(동률 정렬 흔들림 버그 수정, 2026-08-28)
