## 1. 화면 개요

- **화면 ID**: `FRM-03`
- **화면 이름**: Data Template 설정
- **화면 유형**: 모달
- **메뉴 경로**: 양식 관리 > 양식 편집기 > Data Template
- **대상 사용자**: 고객 Excel 서식을 등록·관리하는 내부 담당자
- **비즈니스 목적**: 고객 Excel 서식에 데이터 키를 연결하여 문서 확정값을 기존 서식 그대로 출력한다.
- **등록 단위**: 양식 버전당 Excel 템플릿 1개

> 반복행(표 형태로 여러 행을 작성하는 필드 그룹) 컬럼도 `[데이터키.01]`~`[데이터키.NN]` 고정 슬롯 플레이스홀더로 허용 목록에 항상 포함된다. 반복 시작/종료 문법이나 동적 행 복제는 없다 — 자세한 문법은 §3.4 참고.

---

## 2. 주요 사용자 흐름 (Happy Path)

1. FRM-02에서 `[📊 Data Template]` 클릭
2. 데이터 키 플레이스홀더가 포함된 `.xlsx` 파일 선택 또는 드래그
3. 서버에서 파일 형식과 플레이스홀더 검증
4. 검증 통과 시 별도 저장 없이 템플릿 자동 등록
5. 필요 시 등록된 원본 파일 다운로드
6. 다른 파일로 교체하려면 기존 템플릿 삭제 후 새 파일 업로드

## 3. 플레이스홀더 규칙

### 3.1 기본 문법

- Excel 셀에 `[데이터키]` 형식으로 입력
- 예: 고객명 필드의 데이터 키가 `customer_name`이면 `[customer_name]` 사용
- 문서가 최종 확정되면 플레이스홀더를 확정값으로 치환
- 원본의 셀 서식, 병합, 굵기 등 Excel 레이아웃 유지
- 숨김 처리된 필드는 허용 플레이스홀더 목록에서 제외

### 3.2 일반 필드

- FRM-02에서 설정한 필드의 데이터 키 사용
- 선택(choice) 필드는 개별 옵션이 아닌 병합된 필드의 데이터 키 사용
- 문서의 최종 확정값(`finalValue`)을 Excel 표시값으로 변환

**공통 처리:**

- `finalValue`가 `null` 또는 빈 문자열이면 Excel 셀을 빈값으로 치환
- OCR 원문(`rawOcrValue`)과 정규화 중간값(`normalizedValue`)은 직접 사용하지 않음
- 문서가 최종 확정되기 전에는 고객 Excel 출력 불가

**유형별 출력 규칙:**

| 필드 유형 | 입력값 | Excel 출력값 | 처리 기준 |
|---|---|---|---|
| 텍스트 | 확정 문자열 | 확정 문자열 | 별도 가공 없이 `finalValue` 사용 |
| 숫자 | 정규화된 확정 숫자 문자열 | 확정 숫자 문자열 | 단위·천 단위 기호를 새로 붙이지 않음 |
| 날짜 | 정규화된 날짜 또는 원문 | 확정 날짜 문자열 | FRM-02에서 선택한 출력 형식이 이미 반영된 `finalValue` 사용 |
| 시간 | 정규화된 시간 또는 원문 | 확정 시간 문자열 | FRM-02에서 선택한 출력 형식이 이미 반영된 `finalValue` 사용 |
| 체크(boolean 출력) | `true` | `✓` | `outputMode != symbol`인 경우 |
| 체크(boolean 출력) | `false` 또는 그 외 값 | 빈값 | `true`와 정확히 일치할 때만 체크 표시 |
| 체크(기호 출력) | `V`, `O`, `X` 등 | 동일한 기호 | `outputMode = symbol`이면 실제 확정 기호 유지 |
| 선택 | 옵션 `storedValue` | 옵션 표시명(`label`) | 저장값과 일치하는 옵션명을 찾아 변환 |
| 다중 선택 | 쉼표로 구분된 저장값 | 쉼표와 공백으로 연결한 옵션명 | 예: `male,other` → `남성, 기타` |

**선택 필드 변환:**

1. `finalValue`를 쉼표 기준으로 분리
2. 각 값을 trim 처리하고 빈 항목 제거
3. `storedValue`와 일치하는 옵션의 `label` 조회
4. 변환된 표시명을 `, `로 연결

- 옵션을 찾지 못한 저장값은 삭제하지 않고 원래 값을 그대로 출력
- 단일 선택과 다중 선택은 동일한 옵션 매핑 규칙 사용
- Excel에서는 저장값이 아닌 사용자가 이해할 수 있는 옵션 표시명을 우선 출력

### 3.3 시스템 필드

- FRM-02에서 만든 일반 필드와 별도로, 서버가 항상 허용하는 6개 키가 있음
- 일반 필드처럼 눈에 보이는 UI는 없지만, 검증 시 허용 목록에 자동 포함됨

| 라벨 | 데이터 키 | 값 |
|---|---|---|
| 문서번호 | `document_no` | 문서의 NCode (없으면 빈값) |
| 양식명 | `template_name` | 양식(템플릿) 이름 |
| 인쇄일시 | `printed_at` | 문서 생성 시각 |
| 필기일시 | `written_at` | 문서 수신 시각 |
| 업로드일시 | `uploaded_at` | 문서 수신 시각 (필기일시와 동일 값) |
| 확정일시 | `confirmed_at` | 문서 확정 시각 |

- 모든 시스템 필드 값은 `YYYY-MM-DD HH:mm` 형식 문자열 (시각이 없으면 빈값)

### 3.4 반복행 슬롯 플레이스홀더

- 반복행(표처럼 여러 행을 반복 작성하는 필드 그룹)은 동적으로 행을 복제하지 않고, 컬럼마다 행 번호가 고정된 슬롯 키를 미리 나열하는 방식으로만 지원
- 문법: `[컬럼_데이터키.행번호]`, 예: `[item_name.01]`, `[item_name.02]`
- 행 번호는 기본 2자리 0패딩(`01`, `02`, …)이지만, 반복행 그룹의 최대 행 수(`maxRows`)가 100 이상이면 100번째 행부터 자연스럽게 3자리(`.100`, `.101`, …)로 늘어남
- 검증 정규식은 행 번호를 최대 3자리(`001`~`999`)까지만 유효한 문법으로 인정 — `maxRows`가 1000을 넘는 그룹은 그 이상 행 번호가 `INVALID_PLACEHOLDER_SYNTAX`로 처리됨(실무상 도달하기 어려운 값이라 화면에 별도 안내는 없음)
- `[그룹.컬럼]`처럼 점 뒤가 숫자가 아닌 형태는 별도의 미지원 문법(`REPEAT_FIELD_NOT_SUPPORTED`)으로 구분해 처리 — §5.3 참고
- 표 형태 데이터는 개별 필드 + 데이터 키 수동 접미사(`.01`,`.02`...)로 표현하며(FRM-02 §4.4a 참고), 이 플레이스홀더 문법은 그렇게 만든 개별 필드에도 그대로 적용된다. 본 문서는 Data Template 쪽 플레이스홀더 문법만 다룸

## 4. 화면 구성

### 4.1 진입 버튼

- 위치: FRM-02 헤더
- 버튼: `[📊 Data Template]`
- 클릭 시 Data Template 설정 모달 노출
- 툴팁: `고객 엑셀 서식에 [데이터키]를 넣어 업로드하면 확정값으로 치환해 출력합니다`

### 4.2 모달

- 제목: `Data Template 설정`
- 우측 상단 `[×]`: 모달 닫기
- 바깥 영역 클릭: 모달 닫기
- 최대 높이를 초과하면 모달 내부 세로 스크롤
- 등록 상태에 따라 업로드 영역 또는 관리 버튼 표시

### 4.3 상태 표시

| 상태 | 표시 |
|---|---|
| 미등록 | `상태: 미등록` |
| 검증 실패 | `상태: 검증 실패 ({파일명})` |
| 등록 완료 | `상태: 사용 가능 ({파일명})` |

- 검증 실패: 빨간색 표시와 `[✕]` 제공
- 등록 완료: 초록색 강조
- `[✕]` 클릭 시 실패 파일명과 오류 목록 초기화
- 실패 시도 초기화에는 확인창을 표시하지 않음

### 4.4 파일 업로드

- 안내 문구: `.xlsx 파일을 끌어놓거나 선택하세요.`
- 업로드 방법
  - `[파일 선택]` 클릭
  - 파일을 업로드 영역으로 드래그
- 파일 선택창은 `.xlsx` 파일만 선택 가능
- 업로드 중
  - 버튼을 `검사 중…`으로 변경
  - 업로드 영역 반투명 처리
  - 추가 선택·드롭 차단
- 등록된 템플릿이 있으면 업로드 영역 미노출

### 4.5 등록 템플릿 관리

- `[다운로드]`
  - 등록한 원본 Excel 파일 다운로드
  - 파일 내용과 파일명 유지
- `[삭제]`
  - `템플릿을 삭제할까요?` 확인창 표시
  - 확인: 템플릿 삭제 후 미등록 상태로 전환
  - 취소: 상태 변경 없음
- 파일 교체 버튼은 제공하지 않음
- 교체 순서: 기존 템플릿 삭제 > 새 파일 업로드

## 5. 업로드·검증

### 5.1 검증 조건

- 파일 확장자: `.xlsx`
- 최대 파일 크기: 10MB
- 정상적으로 열 수 있는 Excel 워크북
- 플레이스홀더 문법이 올바를 것
- 모든 플레이스홀더가 현재 양식의 표시 필드 데이터 키(시스템 필드·반복행 슬롯 포함)와 일치할 것

### 5.2 검증 성공

- 검증 완료 후 저장 API 자동 호출
- 별도 `[저장]` 버튼 없음
- 성공 토스트 없음
- 상태를 `사용 가능 ({파일명})`으로 변경
- 업로드 영역을 숨기고 다운로드·삭제 버튼 표시
- 등록 정보
  - 원본 파일명
  - 파일 데이터
  - SHA-256 체크섬
  - 플레이스홀더 수
  - 검증 결과
  - 상태 `active`

### 5.3 플레이스홀더 검증 실패

- 파일을 저장하지 않음
- 업로드 영역을 유지하여 바로 재시도 가능
- 오류 항목을 빨간색 목록으로 표시

| 오류 코드 | 표시 메시지 |
|---|---|
| `UNKNOWN_PLACEHOLDER` | `[{key}] 없는 키` |
| `UNKNOWN_PLACEHOLDER` + 추천 키 | `[{key}] 없는 키 — [{suggestedKey}] 아닌가요?` |
| `INVALID_PLACEHOLDER_SYNTAX` | `[{key}] 잘못된 문법` |
| `REPEAT_FIELD_NOT_SUPPORTED` | `[{key}] 지원하지 않는 반복행 문법` |

> `REPEAT_FIELD_NOT_SUPPORTED`는 `[그룹.컬럼]`처럼 점 뒤가 숫자가 아닌 형태에서만 발생한다. 반복행 슬롯(`.01`~`.NN`) 자체는 미지원 문법이 아니라 허용 목록에 포함된 정상 플레이스홀더다 — §3.4 참고.

### 5.4 파일 검증 실패

| 오류 코드 | 조건 |
|---|---|
| `UNSUPPORTED_FILE_TYPE` | `.xlsx`가 아닌 파일 |
| `FILE_TOO_LARGE` | 10MB 초과 |
| `WORKBOOK_CORRUPTED` | 손상되었거나 읽을 수 없는 워크북 |

> **화면 메시지 미구현**: 위 세 오류 코드는 서버에서 반환하지만 현재 화면에는 대응 문구가 없다. 오류 목록이 비어 보이거나 실패 원인을 확인하기 어려울 수 있다.

### 5.5 저장 실패

- 검증 성공 후 저장 요청이 실패하면 등록 상태로 전환하지 않음
- 현재 화면에는 별도의 저장 실패 메시지가 없음
- 사용자는 동일 파일을 다시 업로드하여 재시도

## 6. 상태별 변화

### FRM-03:미등록

- 등록된 템플릿 없음
- 상태: `미등록`
- 업로드 영역 표시
- 다운로드·삭제 버튼 미노출

### FRM-03:검증중

- 파일 선택 또는 드롭 직후 진입
- 상태: 업로드 영역에서 `검사 중…` 표시
- 중복 업로드 차단
- 검증 성공 시 등록 완료로 전환
- 검증 실패 시 검증 실패로 전환

### FRM-03:검증실패

- 등록된 템플릿 없이 최근 업로드 검증이 실패한 상태
- 상태: `검증 실패 ({파일명})`
- 오류 목록과 `[✕]` 표시
- 업로드 영역 유지
- 다른 파일을 선택하면 이전 오류 초기화 후 재검증

### FRM-03:등록완료

- 검증과 저장이 모두 완료된 상태
- 상태: `사용 가능 ({파일명})`
- 업로드 영역 미노출
- 다운로드·삭제 버튼 표시
- 삭제 완료 시 미등록 상태로 전환

## 7. 출력 연동

### 고객 서식 출력

- 확정된 문서만 고객 Excel 서식으로 출력 가능
- 해당 양식 버전에 활성 템플릿이 있으면 등록 서식 사용
- 플레이스홀더를 문서 확정값으로 치환
- 활성 템플릿이 없으면 시스템 기본 Excel로 대체
- 출력 파일명: `{양식명}_{문서번호}_{확정일}.xlsx`

### 현재 연동 범위

- `/simple/documents/{documentId}`의 Excel 버튼: 고객 서식 출력 API 사용
- DOC-02 메인 문서 상세의 Excel 버튼: 시스템 기본 Excel 출력 API 사용

> **미구현**: FRM-03에서 등록한 고객 서식은 현재 DOC-02 메인 문서 상세의 Excel 버튼에 연결되지 않는다.

## 9. 구현 참고

- 원본 Excel 파일은 치환 과정에서 덮어쓰지 않음
- 원본 다운로드 시 저장된 파일 그대로 반환
- 양식 버전별 템플릿은 최대 1개이며 저장 API는 동일 버전의 기존 템플릿을 갱신할 수 있음
- 현재 UI에서는 등록 상태일 때 업로드 영역을 숨기므로 교체 시 삭제 절차 필요
