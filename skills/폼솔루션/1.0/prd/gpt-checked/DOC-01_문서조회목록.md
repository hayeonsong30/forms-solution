## 1. 화면 개요

- **화면 ID**: `DOC-01`
- **화면 이름**: 문서 조회 목록
- **메뉴 경로**: 문서 조회
- **대상 사용자**: 작성 문서의 처리 상태를 확인하고 결과를 내려받는 내부 담당자
- **비즈니스 목적**: 작성이 시작된 문서를 검색·필터링하고 상세 검수 또는 일괄 다운로드로 연결한다.
- **상세 진입**: `/documents/{documentId}`

> 반복행 데이터 표시·출력 규칙은 현재 스펙에서 제외한다.

> **중요**: `status === "printed"`(인쇄만 되고 아직 필기 스캔이 들어오지 않은 문서)는 이 화면 목록에서 완전히 제외된다. "작성"이 시작된 뒤(받음/처리 중/검토 필요/확정)부터 노출되며, 오류는 재처리 진입점이 이 화면뿐이라 예외적으로 계속 보여준다(2026-08-28, 사용자 결정). 요약 카드·검색·필터 탭은 모두 이 제외 이후의 목록을 기준으로 계산한다.

## 2. 주요 사용자 흐름 (Happy Path)

1. 문서 조회 메뉴 진입 후 작성 문서 현황 확인
2. 검색어 또는 상태 탭으로 문서 필터링
3. `[조회]` 클릭하여 문서 상세(DOC-02) 진입
4. DOC-02에서 OCR 결과 검수 후 최종 확정
5. 완료 문서를 선택하여 CSV 또는 Excel 일괄 다운로드
6. 필요 시 펜 데이터 가져오기로 새 작성 문서 등록

## 3. 화면 구성

### 3.1 상단 영역

- 페이지 제목: `문서 조회`
- `[↑ 펜 데이터 가져오기]`: 펜 연결 패널 노출
- 완료 문서를 1건 이상 선택하면 다음 항목 표시
  - `{n}건 선택됨`
  - `[CSV 다운로드]`
  - `[Excel 다운로드]`
- 다운로드 중
  - 실행 버튼을 `생성 중…`으로 변경
  - CSV·Excel 버튼 모두 비활성
- 다운로드 실패 메시지
  - 미확정 문서 포함: `확정되지 않은 문서는 내려받을 수 없습니다.`
  - 그 외 오류: `다운로드에 실패했습니다.`

### 3.2 요약 카드

| 카드 | 조건 | 강조 색상 |
|---|---|---|
| 전체 문서 | `printed` 제외 전체 조회 문서 수 | 없음 |
| 작성 | received / processing / review_required | 호박색(amber) |
| 완료 | confirmed | 초록색(green) |

- 사용자 상태 카드는 `작성`, `완료` 2개만 제공
- 오류 전용 카드는 제공하지 않음 (오류 상태 문서는 `전체 문서` 카드 수치에는 포함되지만 `작성`·`완료` 어느 카드에도 집계되지 않는다)

### 3.3 검색·필터

- 검색창 Placeholder: `문서 번호·양식명 검색`
- 검색 대상: 양식명 또는 SOBP(`ncode`)
- 부분 일치, 대소문자 구분 없음
- 서버 재조회 없이 현재 목록에서 실시간 필터링

| 탭 | 노출 조건 |
|---|---|
| 전체 | `printed` 제외 모든 조회 문서 |
| 작성 | received / processing / review_required |
| 완료 | confirmed |

- 사용자 상태 필터는 `작성`, `완료` 2개만 제공
- 오류 전용 탭은 제공하지 않으며 오류 문서는 전체 탭의 행에서 확인

### 3.4 문서 목록

- 정렬: 생성일(`createdAt`) 최신순
- 컬럼: 선택, No., 양식 ID, 페이지, 소유자, 상태, 인쇄 / 작성 일시, 작업
- 조건에 맞는 결과가 없으면 `조건에 맞는 문서가 없습니다.` 표시

**컬럼 표시:**

- 선택
  - `confirmed` 문서에만 체크박스 표시
  - 공유 SOBP 문서는 모든 가상번호 문서가 완료된 경우에만 체크박스 표시
  - 공유 SOBP 행 선택 시 그룹 전체를 한 번에 선택·해제
- No.
  - 현재 필터 결과 기준 순번
- 양식 ID
  - 템플릿 ID 앞 8자리
  - 하단에 SOBP를 모노스페이스로 표시
- 페이지
  - 일반 문서: 양식의 페이지 수
  - 공유 SOBP 그룹: 그룹에 포함된 문서 수
- 소유자
  - `데모 관리자`
  - `demo-admin@neolab.local`
- 인쇄 / 작성 일시
  - 상단: 생성일
  - 하단: 수신일, 값이 없으면 `—`
  - 형식: `YYYY-MM-DD HH:mm:ss`
- 작업
  - 일반 문서: `[조회]` 클릭 시 해당 문서의 DOC-02로 이동
  - 공유 SOBP 문서: `[조회]` 클릭 시 가장 낮은 가상번호의 DOC-02로 이동

### 3.5 사용자 상태 표시

DOC-01에서 사용자가 구분하는 문서 상태는 `작성`, `완료` 두 가지다.

| 사용자 상태 | 포함 조건 | 배지 색상 | 선택 가능 |
|---|---|---|---|
| 작성 | received / review_required | 회색(slate) | 아니요 |
| 작성(처리 중) | processing | 브랜드색(파란 계열) | 아니요 |
| 완료 | confirmed | 초록 | 예 |

- 요약 카드와 필터 탭은 작성·완료 기준으로 제공하며, `작성` 그룹 안에서는 received/processing/review_required를 동일하게 묶는다
- 다만 행의 상태 배지 색상은 셋이 완전히 같지 않다: `received`와 `review_required`는 회색(slate)으로 같지만, `processing`만 별도의 브랜드 색으로 구분 표시된다
- received와 review_required는 배지 텍스트도 모두 `작성`으로 표시되어 화면상 구분되지 않는다(색상도 동일)
- 세부 처리 단계는 DOC-02에서 확인

**행 단위 진행·예외 표시:**

- 처리 중인 행: `처리 중` 배지 표시(브랜드 색, 회색 아님)
- OCR 처리에 실패한 행: 빨간색 `오류` 배지 표시
- `처리 중`과 `오류`는 사용자 상태 필터가 아닌 현재 상황을 알리는 행 전용 표시
- 오류 전용 요약 카드와 필터 탭은 제공하지 않음

## 4. 선택 다운로드

### 4.1 선택 조건

- `confirmed` 상태만 선택 가능
- 선택한 문서 ID 전체를 다운로드 API에 전달
- 체크박스가 없는 상태는 일괄 다운로드 대상이 될 수 없음

### 4.2 CSV 다운로드

- 요청: `POST /api/exports/csv`
- 성공: `export-{timestamp}.csv` 다운로드
- 문서별 확정값을 데이터 키 기준으로 출력

### 4.3 Excel 다운로드

- 요청: `POST /api/exports/excel`
- 성공: `export-{timestamp}.xlsx` 다운로드
- 선택 건수와 관계없이 동일한 Excel 형식 사용
- 데이터 키를 열 이름으로 사용
- 선택한 문서의 확정값을 문서별 행으로 구성
- 선택 결과를 Excel 파일 1개로 다운로드

> **미구현**: FRM-03에서 등록한 고객 Excel 서식은 DOC-01 일괄 Excel 다운로드에 적용되지 않는다. 현재 시스템 기본 형식으로 출력한다.

## 5. 문서 식별 방식

문서는 SOBP 사용 방식에 따라 일반 문서와 공유 SOBP 문서로 구분한다.

### 5.1 일반 문서

**개요:**

> **한 줄 요약**: 한 번 작성하는 양식 한 세트를 문서 1건으로 보고, DOC-01에 한 행으로 표시한다.

- 1페이지 양식 한 세트: 문서 1건, 목록 1행
- 3페이지 양식 한 세트: 세 페이지를 합쳐 문서 1건, 목록 1행
- 여러 페이지 양식은 각 페이지에 서로 다른 SOBP 사용
- SOBP를 확인하면 어떤 양식의 몇 번째 페이지인지 알 수 있음
- 같은 세트에 속한 페이지는 하나의 문서로 모아서 표시
- 페이지 구분이 가능하므로 별도의 가상번호를 작성하지 않음

**양식·문서·SOBP 관계:**

| 양식 구성 | 문서 생성 | SOBP 발급 | DOC-01 표시 |
|---|---|---|---|
| 1페이지 양식 1부 | 문서 1건 | 1개 | 1행 |
| 3페이지 양식 1부 | 문서 1건 | 페이지별 3개 | 1행 |
| 3페이지 양식 10부 | 문서 10건 | 총 30개 | 작성된 문서별 1행 |

- 양식 버전의 페이지 수와 페이지 순서를 기준으로 SOBP를 발급
- 발급 시 문서 1건에 페이지별 SOBP 목록을 저장
- 동일 양식이라도 부수가 다르면 별도 문서로 구분

**펜 데이터 처리:**

1. 펜 데이터에서 SOBP 확인
2. SOBP와 연결된 양식 버전 조회
3. 해당 SOBP가 어느 문서의 몇 페이지인지 확인
4. 작성 원본과 스트로크 데이터를 해당 문서의 페이지에 저장
5. 같은 문서의 다른 페이지 데이터가 들어오면 기존 문서에 추가
6. 문서 상태를 `received`로 변경
7. DOC-01에는 페이지 수와 관계없이 문서 1건을 1행으로 표시

**다중 페이지 양식:**

- 하나의 양식 1부에 포함된 모든 페이지를 문서 1건으로 관리
- 각 페이지는 서로 다른 SOBP로 식별
- 펜 데이터가 페이지별로 들어와도 같은 문서에 누적
- 3페이지 데이터가 모두 들어오면 3페이지 문서 1건으로 구성
- DOC-01에서는 3개 행이 아니라 문서 전체를 1행으로 표시
- 페이지 컬럼에는 양식의 전체 페이지 수 표시
- `[조회]` 클릭 시 DOC-02에서 문서의 첫 페이지 표시
- DOC-02의 이전·다음 버튼으로 같은 문서의 페이지 이동

**예시:**

1. 3페이지 양식 1부 발급
2. 1페이지·2페이지·3페이지에 서로 다른 SOBP 할당
3. 펜 데이터에서 세 SOBP의 작성 데이터 수신
4. 각 SOBP를 동일한 양식·동일한 문서의 페이지로 연결
5. DOC-01에 `페이지 3`인 문서 1행 표시

### 5.2 공유 SOBP 문서

**개요:**

- 고토부키향 양식처럼 하나의 SOBP를 복사하여 여러 장 사용하는 방식
- 모든 용지가 같은 SOBP를 사용하므로 SOBP만으로 개별 문서를 구분할 수 없음
- 사용자가 각 용지에 작성한 `가상번호`로 문서를 구분
- 동일한 SOBP와 서로 다른 가상번호를 하나의 문서 그룹으로 관리

**펜 데이터 수신 항목:**

- SOBP
- 가상번호
- 작성 원본 또는 스트로크 데이터
- 작성·수신 시각
- 대상 양식 식별 정보

**처리 순서:**

1. 펜 데이터에서 SOBP와 가상번호 확인
2. SOBP로 대상 양식과 문서 그룹 조회
3. 가상번호별 문서 생성 또는 기존 문서 연결
4. 작성 원본과 스트로크 데이터 저장
5. 동일한 SOBP 문서를 하나의 그룹으로 구성
6. 그룹 안의 문서를 가상번호 오름차순으로 정렬
7. DOC-01에서는 그룹 전체를 한 행으로 표시

**가상번호 규칙:**

- 같은 SOBP 안에서 문서를 구분하는 번호
- 가상번호가 다르면 서로 다른 문서로 처리
- 동일 가상번호가 중복되면 자동으로 합치지 않고 확인 필요 처리
- 가상번호가 없거나 인식되지 않으면 문서 순서를 확정하지 않고 검수 필요 처리
- DOC-01 페이지 컬럼에는 그룹에 포함된 가상번호 문서 수 표시

### 5.3 방식 비교

| 구분 | 일반 문서 | 공유 SOBP 문서 |
|---|---|---|
| SOBP | 문서의 페이지마다 다름 | 여러 문서가 동일 |
| 양식 확인 | SOBP에 연결된 양식 버전 | SOBP에 연결된 양식 버전 |
| 문서 구분 | 발급된 문서와 페이지별 SOBP | 동일 SOBP 안의 가상번호 |
| 가상번호 | 사용하지 않음 | 필수 |
| 목록 표시 | 양식 1부당 행 1개 | 같은 SOBP 그룹당 행 1개 |
| 페이지 수 | 양식의 전체 페이지 수 | 그룹에 포함된 가상번호 문서 수 |
| 상세 이동 | 문서 내부 페이지 이동 | 가상번호별 문서 이동 |

### 5.4 공유 SOBP 목록 표시

- 같은 SOBP 문서를 한 행으로 묶어 표시
- 그룹 안에서는 가상번호 오름차순 정렬
- `[조회]` 클릭 시 가장 낮은 가상번호 문서부터 표시
- DOC-02의 `No.`에서 가상번호 선택
- 이전·다음 버튼으로 가상번호 순서대로 이동
- 모든 가상번호 문서는 동일한 SOBP 표시

**그룹 상태(대표 상태 계산):**

- 하나라도 오류가 있으면 `오류`
- 오류는 없지만 작성·검수 중 문서가 있으면 `작성`
- 모든 가상번호 문서가 확정되면 `완료`
- 실제 우선순위는 오류 > 검토 필요 > 처리 중 > 받음 > 인쇄됨 > 확정 순으로 판정한다. 이 순서대로 그룹에 존재하는 상태 중 가장 앞선 것을 대표 상태로 쓴다.
- 그룹 안에 오류·검토 필요·처리 중·받음 상태가 하나도 없고 `printed`(인쇄만 됨) 문서만 확정 이전 상태로 남아 있으면, 대표 상태가 `printed`가 되어 그룹 행 전체가 목록에서 제외된다(현재 코드 동작이며 별도 정책은 아직 없음)

**선택·다운로드:**

- 모든 가상번호 문서가 완료된 경우에만 체크박스 표시
- 그룹 행 선택 시 그룹에 포함된 문서 전체 선택
- CSV·Excel 다운로드 시 가상번호 순서로 결과 구성

### 5.5 미구현·정책 확인

- 가상번호 저장 필드 미구현
- 펜 데이터에서 가상번호를 가져오는 규격 미구현
- 가상번호 누락·중복 검증 미구현
- 가상번호 기준 정렬 미구현(현재 그룹핑은 SOBP(`ncode`) 값만으로 이루어지며, 그룹 안 정렬은 데이터 조회 순서에 의존한다)
- 공유 SOBP 그룹 전체를 한 번에 확정할지, 가상번호별로 확정할지 정책 확인 필요
- 그룹 대표 상태가 `printed`로 계산되어 그룹 전체가 목록에서 사라지는 엣지 케이스에 대한 정책 확인 필요

## 6. 펜 데이터 가져오기

### 6.1 패널

- `[↑ 펜 데이터 가져오기]` 클릭 시 `PenConnectPanel` 노출
- 연결된 펜 목록 컬럼: 펜 ID, MAC, 배터리
- 실제 하드웨어 SDK는 미연동
- 진입 또는 새로고침(`[↻ 새로고침]`) 후 0.6초 뒤 연결 실패 메시지 표시
  - `USB 연결 상태 수신 시작에 실패했습니다.`
- `[취소]`: 패널만 닫기

### 6.2 테스트 파일로 대체

- 패널 버튼 문구는 `테스트용 이미지로 대체`이며, 이미지 파일 또는 PDF를 선택할 수 있다(`accept="image/*,application/pdf"`)
- 선택한 파일은 가장 최근에 노출되는 인쇄 가능(`printable`) 양식 1건에 자동 등록되며, 인쇄 가능한 양식이 없으면 `인쇄 가능한 양식이 없습니다.` 오류를 표시한다
- 문서 생성 또는 가져오기 API 호출이 실패하면 `가져오기에 실패했습니다.`를 표시한다

> **운영 스펙 제외**: 테스트 파일로 대체하는 기능은 데모를 위한 임시 기능이다. 실제 펜 데이터 가져오기 기능 명세와 운영 범위에는 포함하지 않는다.

### DOC-01:오류 행

- 조건: error

- DOC-02에서 OCR 재시도

### DOC-01:미노출(printed)

- 조건: 인쇄만 되고 아직 필기 스캔이 들어오지 않은 문서(`status === "printed"`)

## 9. 구현 참고

- 사용자 상태 분류는 작성·완료만 사용하며 오류는 행에서만 표시
- `printed` 상태 문서는 DOC-01 목록 전체(요약·탭·검색)에서 제외되는 것이 명확한 사양이며, 실수로 노출되지 않도록 주의
- `작성`으로 묶이는 received/review_required/processing 중 processing만 배지 색이 다르다(브랜드색) — 구현 시 세 상태를 전부 같은 회색으로 처리하지 않도록 주의
- 테스트 파일(이미지/PDF) 업로드는 데모 전용이며 운영 스펙에서 제외
- 공유 SOBP 적용 전 가상번호 저장 필드와 펜 수신 규격 구현 필요
- 그룹 확정 단위는 운영 정책 확정 필요
- 공유 SOBP 그룹의 대표 상태가 `printed`로 판정되면 그룹 자체가 목록에서 사라지는 엣지 케이스가 있어 정책 확인 필요
